# 数据库备份与恢复

论坛数据库采用 SQLite WAL。不要只复制运行中的 `forum.db`：尚未合并的事务可能仍在 WAL 文件中。镜像包含 SQLite 在线备份工具，生成一致性快照并执行 `integrity_check`，不会覆盖已有文件。

在受控运维通道中，以容器运行用户执行以下命令；目标目录须已存在且允许该用户写入：

```sh
node scripts/backup-database.cjs /app/data/backups/forum-20261116.db
```

每次使用不同文件名。备份含用户内容和账号数据，应限制访问，并按既有加密备份流程复制到与生产机故障域独立的位置；不要提交到仓库。定期在隔离环境中打开备份、检查完整性并验证恢复。

恢复生产数据前，先记录当前版本并用在线备份工具保存回滚点；停止写入和容器后，再归档原数据库及其 WAL/SHM。随后由维护者通过既有受控运维通道恢复并检查内容和服务健康。生产已有备份策略及实际恢复演练状态需要运维人员确认；本工具不会自动覆盖生产库，也不会自行创建定时任务。
