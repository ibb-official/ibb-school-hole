# 内容审核与角色管理

默认注册用户均为 `user`。只有活动状态的 `moderator` 或 `admin` 可以访问 `/moderation` 及其接口；前端隐藏入口不是权限边界。审核员可以通过或拒绝待审内容、隐藏或恢复公开内容、处理举报，并可查看作者身份以处理违规。每次处理操作写入安全审计日志。

举报接口与发帖开关分离：即使暂时关闭发帖，已登录用户仍可举报公开的帖子和评论。作者可在 `/account/submissions` 查看自己的投稿及审核状态。

## 授予与撤销角色

角色只能由有数据库访问权限的受信任运维人员，通过既有受控运维通道在运行容器内操作。首次开放时，先配置并开启注册、让目标用户正常注册并确认用户名，再通过离线脚本授予角色；确认至少有一个处于活动状态的审核员或管理员之后，再开启发帖。生产发帖门禁同时要求验证码与 AI 审核配置可用。

授权命令：

```sh
node scripts/manage-moderators.cjs grant <用户名> moderator
node scripts/manage-moderators.cjs grant <用户名> admin
node scripts/manage-moderators.cjs revoke <用户名>
```

脚本读取容器现有的 `FORUM_DB_PATH`，只打开已存在的数据库，修改角色并写审计日志；它不创建账号、设置密码或把凭据写进仓库。`revoke` 将角色降为 `user`。不要将账号密码、会话令牌或数据库复制到源码仓库。

## 日常处理

1. 进入 `/moderation`，处理待审内容和举报；如需解释拒绝或隐藏原因，可先填写处理说明。
2. 举报的“隐藏内容”和“标记已处理”是两个独立操作，处理举报前先确定是否需要隐藏。
3. 管理员可以按内容编号隐藏公开内容，或恢复已隐藏内容；拒绝的内容可以重新送审。
4. 发现账号公开昵称或内容泄露个人信息时，可以停用账号：系统撤销其全部会话、隐藏其公开帖子和评论、拒绝待审内容，并重新计算受影响的计数。普通审核员不能处置其他审核员或管理员。
5. 恢复账号不会自动恢复内容；确认安全后可逐项恢复。帖子被隐藏时，其评论不会对公众显示；评论审核状态变化会重新计算帖子的公开评论数和活跃时间。
